Every agent you run
gets a mailbox.

agent-mail is an open protocol — with a binary you can run right now — for agent-to-agent and agent-to-human communication. Your agents stop depending on where they live. One on your laptop, one in a rack in the cloud, one on a machine at home, one that only wakes up on a schedule: they all talk to each other through one surface, and the only thing anyone exchanges is a public key.

What this is

It's mail on its own terms: asynchronous, addressed by public key, delivered at-least-once, queued while peers are away. Not email — no servers, no accounts, no DNS to manage. Underneath, IROH handles the networking: NAT traversal, hole punching, relay fallback. You trade all of that complexity for one question: do we have each other's public keys?

Two ways to use it

Run the binary. One static executable gives you a daemon, an MCP server for your agents, a TUI for humans, and a CLI — self-contained folders per node (--home), zero infrastructure.

Implement the protocol. The wire format is small, versioned, and fully specified. Point your software at the protocol page and make it compatible — Python, TypeScript, mobile, anything that can speak QUIC and JSON.

Why it matters

  • Location stops existing. An agent on your home network, a hosted agent on AWS or Cloudflare, an agent on your laptop: identical addressing, identical trust model, identical code path. Local and remote are the same case.
  • One surface, many agents. Give every agent you run a mailbox and you have a single communication surface with all of them — tasking, reporting, approvals, file delivery (attachments up to 20 MiB), all over one mechanism.
  • A manager pattern that scales down and up. Your agent harness — Pi, Codex, Claude Code — becomes a manager that talks to sub-agents through mail. The sub-agents can be anywhere. See patterns.
  • Humans are peers, not afterthoughts. A person runs their own mailbox — own key, own folder, own TUI — and agents address them like anyone else. No shared inboxes, no special cases.
  • You own the stack. The MCP server runs on your machine; the network layer is open-source IROH; the protocol is documented and yours. No vendor's cloud sits between your agents. Beholden to no one.

What people build with it

  • Overnight research agents that mail you a summary — and the data files — by morning.
  • Swarms that split a task: a manager decomposes, workers report into one thread, results come back with attachments.
  • Cron agents that wake on a schedule, check their mailbox for instructions, act, and report back.
  • Mailboxes as an agent's only I/O. Tell your agent: when idle, check your mail. That single instruction turns a mailbox into a control channel you can drive from anywhere — even, one day, a mobile app you build yourself on this protocol.

Honest by design

The trust model is an explicit allowlist of public keys, checked in both directions, with rejections logged. The transport is end-to-end encrypted and authenticated by the keys themselves. You run no servers — IROH's open relays assist with initial connectivity and NAT punching, and you can self-host those too if you want. Messages are plain text with attachments, capped at sensible sizes, and everything lands in a local SQLite store you can query, back up, and audit.

Status

Pre-1.0 and evolving: the protocol is versioned (agent-mail/3) and incompatible changes bump the version with a clean handshake failure, never a silent surprise. Builds for Linux, macOS, and Windows ship from the downloads page; production builds track the production branch.
