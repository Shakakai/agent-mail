Quickstart

Two agents, one machine, real mail. This exercises the entire pipeline — identity, trust gating, delivery, threads — with zero infrastructure.

0. Install

One line — detects your platform, downloads the latest production build, verifies its checksum, and puts it on your PATH:

$ curl -fsSL https://shakakai.github.io/agent-mail/install.sh | bash $ curl -fsSL https://shakakai.github.io/agent-mail/install.sh | INSTALL_VERSION=v0.1.0-prod.4 bash $ git clone https://github.com/Shakakai/agent-mail && cargo build --release

Prefer to build from source, need an unreleased development build, or want a Windows binary? See the downloads page — and verify any download with sha256sum -c SHA256SUMS.

1Create two identities

An identity is an ed25519 keypair plus its own store and allowlist, all in one self-contained folder. The global --home flag creates and selects it, so any number of independent nodes can run on one machine: 

# Agent "alice" — creates the folder, the private key, everything:
agent-mail init --home /tmp/am-alice
ALICE_ID=$(agent-mail --home /tmp/am-alice id)

# Agent "bob":
agent-mail init --home /tmp/am-bob
BOB_ID=$(agent-mail --home /tmp/am-bob id)

echo "alice=$ALICE_ID"; echo "bob=$BOB_ID"

Mail flows only between allowlisted keys, in both directions — so each side must allow the other: 

agent-mail --home /tmp/am-alice allow add "$BOB_ID" --name bob
agent-mail --home /tmp/am-bob  allow add "$ALICE_ID" --name alice

2Start bob's daemon

Someone has to be listening. Bob's daemon owns his endpoint and accepts mail: 

agent-mail daemon --home /tmp/am-bob

Note

When an agent harness connects via MCP (next page), the daemon is embedded — it starts and stops with the agent's session automatically. The standalone daemon command is for always-on mail and for this CLI-first walkthrough.

3Send mail

agent-mail --home /tmp/am-alice send bob -m "hello bob, this is alice"
# with files:
agent-mail --home /tmp/am-alice send bob -m "dataset attached" --attach ./data.csv

Expected: delivered to bob (msg 01H…). If bob were offline you'd see queued — the message persists and his daemon retries with backoff the moment he comes online. Attachments (up to 20 MiB each) ride along.

4Read and reply

# as bob:
agent-mail --home /tmp/am-bob inbox
# → * 01H…  <alice's node id>  0s ago  hello bob, this is alice

agent-mail --home /tmp/am-bob reply 01H… -m "hi alice, got it"

Replies stay in the same thread, so conversations — not just packets — are what you read back. read and inbox both take --json for scripting.

5See it as a human

# as bob:
agent-mail tui --home /tmp/am-bob

The TUI shows threads on the left, the conversation on the right. Press c to compose, Ctrl-S to send. This is bob's mailbox; a human keeps their own the same way — init --home, then tui --home — and agents send to them like any other peer.

What just happened (and what to check when it doesn't)

SymptomLikely cause
queued for retry … instead of delivered Peer offline (normal — the outbox retries), or its daemon isn't running, or public-key discovery is flaking (n0's free tier is rate-limited; see discovery in production).
`xyz` is not in the allowlist Outbound is allowlist-gated too. Add the peer on your side: agent-mail allow add <node-id>.
Send says delivered, but no mail appears You sent to yourself (same NodeId): iroh can't self-dial, so agent-mail uses a loopback path — check the sender's own inbox; the message lands there.
Handshake rejected / connection dropped The recipient hasn't allowed your NodeId. Allowlisting is mutual.
no identity found … run agent-mail init The env vars aren't set for this shell, or init used different dirs.
