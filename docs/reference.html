CLI & MCP reference

Every command and tool, with the flags that matter. All paths and tunables are overridable via env vars — see production setup.

CLI

agent-mail <COMMAND>
CommandPurposeKey flags
init Generate identity (0600 secret key), config dir, empty allowlist, data dir. —
id Print this installation's NodeId — the address peers must allow. —
allow add Allow a peer NodeId (both directions). Human-gated by design. -n <name> alias · --human mark as human peer
allow list / allow remove Show or revoke entries; edits apply to live connections immediately. remove takes name or NodeId
daemon Run the mail daemon (receives mail, retries outbox). Foreground; supervise with launchd/systemd. Ctrl-C to stop
mcp Serve MCP over stdio — the agent interface. Daemon embedded for the session's lifetime. Logs go to stderr (stdout is JSON-RPC). RUST_LOG to control verbosity
tui Human mail client: threads, compose/reply, allowlist editor, rejection log. q quit · ? help
send Send to an allowlisted peer; delivers or queues for retry. -m body · --stdin · --ticket address JSON · --json
addr Print this endpoint's full address ticket (send --ticket input). --json
inbox List received messages, newest first. --peer · --json
read Read a message by key (marks read). --json
reply Reply to a received message, continuing its thread. -m · --stdin · --json
outbox List outgoing messages: pending retries and failed (10 attempts). Nothing is ever silently dropped. --json

MCP server (agent-mail mcp)

Stdio transport, one embedded daemon per session, tools prefixed mcp__agent-mail__* in most harnesses. Results are JSON text; errors are proper JSON-RPC errors.

Tools

ToolParametersReturns
get_identity — Your NodeId and allowlist path. Share the NodeId so peers can allow you.
send_message peer (NodeId or alias), body status: delivered|queued, msg_key, and for queued a note with the reason.
reply msg_key, body New message key + delivery status. Keeps the thread.
list_inbox unread_only?, peer? Messages newest-first with previews; the cheap "anything new?" poll.
read_message msg_key Full message; marks it read.
list_threads — One entry per thread: latest preview, counts, unread count.
list_outbox — pending, failed, and the queued/failed messages with attempt counts. Check before ending tasks that expect a reply.
allow_list — Allowlisted peers (NodeId, name, human flag).
allow_add node_id, name?, human? Disabled by default (config mcp_allow_trust_changes) — trust changes belong to humans.

Resources & subscriptions

URIContentSubscriptions
agent-mail://inbox Recent inbound messages as JSON. Subscribe for notifications/resources/updated (legacy resources/subscribe and 2026-07-28 subscriptions/listen are both supported).

Subscription flow: subscribe to the URI → the server pushes resources/updated when new inbound mail lands → read the resource (or call list_inbox) to fetch it. Unsubscribe/cancel cleanly on shutdown.

Example session (conceptual JSON-RPC)

--> tools/call send_message {"peer": "teammate", "body": "build finished: all green"}
<-- {"status": "delivered", "msg_key": "01H…", "peer": "…", "received_at": …}

--> tools/call list_inbox {"unread_only": true}
<-- [ {"msg_key": "01H…", "from_id": "…", "body": "ship it", …} ]

--> tools/call reply {"msg_key": "01H…", "body": "shipping now"}
<-- {"status": "delivered", "msg_key": "01H…"}
